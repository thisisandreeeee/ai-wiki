# 😸 GAO Says Four Major Chatbots Produced Viable Attack Plans in Covert Tests

The U.S. Government Accountability Office (GAO), the federal government's watchdog agency, [released a report](https://www.gao.gov/products/gao-27-108814) Wednesday saying it got ChatGPT, Claude, Gemini, and Grok to produce attack plans it judged workable. The tests ran in spring 2026, so they cover the versions available then.

Here's what happened:

* GAO picked the four most-used chatbots as of April 2026 and randomly gave each one a scenario, either building and detonating an explosive device or attacking the electrical grid.

* Every chatbot's safeguards kicked in at first, with a refusal, removed content, or a suspended account.

* GAO says it got past them using common bypass techniques, which the report does not name.

* Two chatbots produced explosive plans and two produced plans to attack power substations, all in under 12 hours.

Quick translation. Safeguards are the rules that make a chatbot refuse harmful requests. Bypassing them, often called jailbreaking, means wording a request so the chatbot goes along anyway. _Think of talking your way past the bouncer instead of kicking down the door._

GAO counted a plan as viable when it named specific targets, locations, and attack methods, and its experts judged it sufficient to plan and execute an attack. GAO then checked feasibility through research, surveillance, and expert interviews.

Here's the detail worth repeating. GAO says the underlying information was not new. The chatbots gathered what already exists and organized it into a plan fast. _Translation: a research assistant that works quickly and never gets tired._

A few caveats. The report labels the chatbots A through D and does not say which one produced which plan. It also does not state the model versions tested, so results may not match today's models. This summary comes from GAO's report page, which lists no recommendations, and the full report runs 61 pages.

**Why this matters:** Safeguards are what stand between a chatbot and a harmful request, and GAO says common bypass techniques got past them on all four platforms. Company officials told GAO they will keep improving safety, so the thing to watch is whether that holds up when someone repeats this test on current models.

# 🎓 AI Skill of the Day: Make Your Coding Agent Prove Its Work

The [Claude Code team](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/) says the way to hand more work to coding agents is to give each agent a way to check itself, so you stop reading every change by hand. Three steps you can borrow from their workflow:

1. Start with an end-to-end test, which runs a real user flow in the running app, like adding an item to a cart and reaching the confirmation page. When it fails, it shows where the flow broke instead of a vague timeout.

2. Add a property-based test, which checks a rule that should always hold, like an account balance never going negative, against thousands of generated inputs. Nobody wrote it with the agent's assumptions baked in, so it catches edge cases the agent missed.

3. If you're replacing old code, run the old and new versions on the same inputs and have the agent chase down any differences, ignoring noise like extra whitespace.

Then set limits. The team lets Claude fix failing checks for up to three rounds before it hands the problem to a human, and the agent never gets to rewrite the rules that judge it. _A passing test only proves what it checks, so skim the test too._

```
Make this change: [describe it]. Before editing, tell me how you will verify [expected behavior]. After the change, run an end-to-end test of that flow plus a test of one rule that should always hold, and report the actual results. If a check fails, fix it up to three times, then stop and tell me. Do not edit the tests to make them pass, and flag anything you could not test.
```
