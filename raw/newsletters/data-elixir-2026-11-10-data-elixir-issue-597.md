### [When Do Causal ML Models Beat LM / GLM / GBM?](https://philipppro.quarto.pub/blog_philipppro/posts/causalml-toy-cases/?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

### [The Watchmaker: Building a Mechanical Watch in a Database](https://sqlartist.github.io/posts/the-watchmaker-building-a-mechanical-watch-in-a-database/?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

Instead of programming how a mechanical watch should work, Trevor Dwyer modeled its parts as geometric shapes and let SQL figure out how they interact. The result is a working 34-part watch that runs in SQL. Here's how it works, along with a great exploration of spatial databases, computational geometry, and the limits of SQL Server. Includes a link to the code.
_Trevor Dwyer_

### [e-means: Rethinking K-Means](https://e-means.github.io/?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

Sometimes a little randomness helps an algorithm find a better solution. That's the idea behind e-means, a new approach to k-means clustering that uses small, noisy updates to avoid getting stuck in poor solutions. The result is faster clustering that often produces better results. This is a great post that uses interactive examples to show how it works and why.
_Swann Bessa_


--------------------
### [Putting E-Means to the Test](https://dev.to/frankchu/10x-faster-k-means-i-re-ran-it-and-got-15x-24bb?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

Frank Chu tried reproducing the impressive results in the post above and got a very different answer. Instead of a 10x speedup, he measured 1.5x. His investigation into the difference is a great case study in why benchmarks are tricky, implementation details matter, and how reproducing research can teach you as much as the research itself.
_frank chu_

### [Nuclei, five years later: what a mean Dice hides](https://datascienceguts.com/posts/2026-11-06-nuclei-mean-dice/?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

A model can have a great average score and still fail badly on certain cases. This post revisits a cell-nuclei segmentation model that performs well overall, but fails badly on specific cases. It's a great example of model evaluation, with reproducible code in R and Python.
_Data Science Guts | Michał Maj_

# Data Visualization


--------------------
### [Postal codes and tessellations](https://dieghernan.github.io/codigospostales/?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

Voronoi polygons divide a map into regions based on the nearest point, which makes them useful for things like estimating service areas, assigning customers to locations, and mapping geographic coverage. This tutorial uses postal code data to show how to build Voronoi polygons, handle messy boundaries, and check the results.
_One World | Hernangómez_


--------------------
### [Battles and space-filling curves](https://datascienceconfidential.github.io/r/graphics/2026/10/26/space-filling-curves.html?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597)

This is a clever way to reduce geographic data from two dimensions to one. By using a Hilbert curve to turn coordinates into a single dimension, the resulting visualization shows how conflicts spread across regions and through time. It's a great example of how transforming data can reveal patterns that conventional maps miss.
_Richard Vale_

### [AVA: Visual Analytics for AI Agents](https://github.com/antvis/AVA?utm_campaign=Data_Elixir&utm_source=Data_Elixir_597#ava-ai-native-visual-analytics)

AVA gives AI agents a toolkit for exploring and visualizing data. They can connect to files and databases, inspect data quality, run queries, suggest questions worth exploring, and generate charts to help answer them. It's open source, works with multiple execution engines, and lets you inspect the queries behind the visualizations.
